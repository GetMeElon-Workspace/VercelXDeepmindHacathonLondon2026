## Problem Statement
Financial modeling and mass/heat balances for industrial plants are messy and highly specific—and this extends across verticals (chemicals, energy, manufacturing, etc.). When analysts update a dataset (e.g., trying a new geography like France), there are often partial gaps in the data that break the model. They need a way to easily trace inputs, visualize the flow, branch off new scenarios, intelligently fill in missing data, and **audit every AI-generated value back to its source**.

## What Makes This Cool
The "whoa" factor is turning Excel into an interactive, node-based visual canvas (like Unreal Engine Blueprints) powered by Vercel AI SDK and Gemini 3.1 Pro. Instead of just "chatting" with data, the user chats with an agent that dynamically generates and wires up new nodes with proposed missing data—which the user can formally "Accept" or "Reject" to merge into the main model.

2. **The Physics Hallucination:** Gemini can reliably fill in missing engineering data. (Pushback: User insisted that *all* AI-generated data must be explicitly approved).
3. **The Demo Reality:** Visual wow factor > backend purity. (Agreed, but hybrid approach chosen).

## Data Model & Initial State
- **Initial State:** The base "Plant A" model is pre-seeded in the database to ensure the demo starts instantly. 
- **Schema:** 
  - `Nodes` (id, type, data_json, position_x, position_y, branch_id)
  - `Edges` (id, source_node, target_node, branch_id)
  - `Branches` (id, parent_id, name, status)
  - AI proposals are generated as `Nodes` with `status: pending`.

## Approaches Considered
### Approach A: Minimal Demo (Hardcoded)
A static React Flow app. We hardcode a base "Plant A" model. Gemini only "fills in" pre-determined missing values via a simulated prompt. A modal pops up for the user to "Approve". (Rejected due to being smoke and mirrors).

### Approach B: Vercel AI SDK + Generative UI
A real chat interface next to a React Flow canvas. You chat with Gemini using the Vercel AI SDK. We stream JSON data back that dynamically spawns new nodes/edges on the canvas, showing proposed values with "Accept/Reject" buttons built right into the nodes.

### Approach C: The Supabase + Gemini Hybrid
Base models are stored in Supabase. You click "Branch to France", a server action asks Gemini to fill the gaps, and it writes "pending" rows to Supabase. Real-time subscriptions update the UI to show the pending data for approval.

## Recommended Approach
**Hybrid of B & C:** Use Supabase to store the actual model state and branches (nailing the database side and branching logic). Use Vercel AI SDK with Generative UI to create the interactive "Approval" nodes on the React Flow canvas. We will "make up" or simulate some of the deeper physics data to ensure the demo looks populated, but route it strictly through the user-approval UI.

**Fallback Plan (Feasibility):** If Supabase real-time subscriptions prove too complex to wire up with React Flow in time, we will fall back to managing node state purely in local React state during the AI generation phase, and only write to Supabase upon clicking 'Accept'.

## QA Feature
A core trust mechanism: anyone (analyst, manager, reviewer) can inspect the data flowing through the model.

### Inspect Mode
- Accessible from any node or from a global toolbar button.
- Shows **input data** (what went into the AI prompt / model) and **output data** (what the AI proposed or what was accepted) side-by-side.
- AI-generated rationale and source links are displayed inline for traceability.

### Two Output Views
| View | Description | Use Case |
|---|---|---|
| **Full Model** | The entire node graph / scenario branch with all calculated, proposed, and accepted values. | High-trust users who want the complete picture. |
| **Inputs Tab** | A simplified, copy-pasteable table of just the input assumptions (e.g., commodity prices, efficiency rates, geography parameters). | Low-trust users who want to take the inputs and run them in their own spreadsheet or model. |

### Why This Matters
- Builds a **trust gradient**: users who trust the system use the Full Model; users who don't can grab just the Inputs Tab and verify independently.
- Every AI-generated value links back to its rationale and sources, supporting **reporting and audit trails** at a later date.

## AI Integration Details (Vercel AI SDK x Gemini 3.1 Pro)
**System Prompt:**
> You are a senior financial analyst with deep knowledge in financial modeling and domain expertise in the vertical being analyzed (e.g., chemicals, energy, manufacturing). The user will provide a base industrial plant model and ask you to create a new scenario branch (e.g., "build this plant in France").
> Your job is to analyze the new context, pull in relevant localized commodity prices, and estimate missing data (like heat efficiency or feedstock yield changes).
> You MUST return a valid JSON array of `Node` objects representing the missing data gaps you are proposing. Save the markdown explanation and link to the data sources so it is traceable—this is also used for reporting at a later date.

**Zod Schema (for `streamObject`):**
```typescript
const NodeProposalSchema = z.object({
  proposals: z.array(z.object({
    id: z.string().describe("A unique UUID for this proposed node"),
    title: z.string().describe("e.g. 'Heat Balance (FR)'"),
    type: z.enum(['calc', 'physics', 'financial']),
    data: z.array(z.object({
      label: z.string().describe("e.g. 'Efficiency'"),
      value: z.string().describe("e.g. '85%'"),
    })),
    rationale: z.string().describe("Markdown explanation for why this value was proposed, including reasoning and methodology."),
    sourceLinks: z.array(z.string().url()).optional().describe("URLs or references backing the proposed value, for traceability and reporting.")
  }))
});
```
